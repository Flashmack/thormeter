# Aion 2 EU protocol notes

The protocol implementation is pinned to [SkeeveTV's MIT-licensed Aion-DPS-Meter](https://github.com/SkeeveAN/Aion-DPS-Meter/tree/3aa8c732a539de8b8f09f4823f57d4ba1e6b4830/Client/Aion2) at commit `3aa8c732a539de8b8f09f4823f57d4ba1e6b4830`. Its `opcodes.json` labels its calibration **EU early access 2026-09-30**, based on a captured session and in-game combat log. The accompanying source was inspected on 2026-10-04. The calibration is a starting point, not evidence that a later game build uses the same wire format.

Thor Meter captures TCP port `13328` with a driver-level BPF filter. It lists candidate client/server flows, automatically selecting one when it is the sole flow and its server data aligns with observed protocol frames. Multiple flows require an explicit choice. Up to 1 MiB of recent packets per candidate is kept so early login metadata can be decoded after selection; truncation is reported as possible data loss. The decoder consumes only the server-to-client direction. The reference framing uses an unsigned LEB128 prefix, a total record size of `length + prefix bytes - 4`, and a two-byte big-endian opcode at the start of the emitted frame. TCP fragments and retransmissions are handled before framing; buffers are bounded. A flow is marked as protocol-aligned only after its stream yields a frame with an opcode from the pinned observed-opcode list.

Implemented EU messages: direct hit `0x0438`, damage-over-time tick `0x0538`, nickname `0x4536`, player appearance `0x048d`, local character `0x3336`, entity spawn `0x4136`, and LZ4 bundle `0xffff`. The pinned `eu-opcodes.json`, `heal_skill_families.json`, and `rdps_watchlist.json` supply the calibration and filter tables. The decoder rejects malformed records and counts unknown opcodes. It filters the reference's companion skill notices, consumables, and known non-damage effects; recognized heal families become healing events on non-NPC targets. NPC spawn IDs are excluded from player totals; a summon is attributed only when the spawn message names a different owner ID. Validated NPC spawn names are retained for target labels. Class inference uses the reference's class-skill ID prefixes and local-character class codes. Names and class can arrive after damage. Name decoding accepts strict UTF-8 with Unicode letters, combining marks, or digits after normalization; it deliberately rejects punctuation and malformed text rather than guessing names from arbitrary payload bytes. Decoder counters expose identity messages accepted without a usable name. Heal amount semantics, tick coverage, shields, and overheal remain unverified against the live EU client.

The upstream reference includes additional heuristics and game data outside this milestone. Thor Meter does **not** guess summon owners from class or timing; unresolved summons and any missing ownership messages can therefore undercount an owner's total. Some sources first seen mid-fight may remain unidentified, and captures that start mid-connection may miss frames while synchronizing. The current decoder has no verified Party/Force membership fields or complete NPC/skill catalog, so it cannot classify group membership, bosses, or training dummies reliably. Loss, malformed input, or a client patch can also affect totals. Compare a controlled combat sequence with the game's visible analyzer before relying on numbers. Live correctness for the current EU client remains under validation.

Raw replay files contain payload bytes and endpoint addresses. Recording is opt-in for the selected flow, local only, and never uploaded. Keep them private. The runtime has no network requests, packet transmission, or process inspection.

## Open live investigations

- **Healing accuracy:** live healing totals can exceed the visible in-game log, substantially for Spiritmasters. The decoder still treats listed skill families as heals and accepts a broad range of extracted amounts. Class inference no longer upgrades a confirmed NPC to Player, and bounded decoded-heal summaries are available for diagnosis. These summaries include decoder candidates even if later excluded by Pause or the combat engine. Effective healing, overheal, shields, pet HP exchange, duplicate notices, and exact amount semantics remain unverified. Compare an isolated heal with a timestamped recording and combat log before changing numeric extraction.
- **Replay state:** new Pause/Resume and Reset markers reproduce those actions in replay; raw packets remain recorded during Pause. Older recordings without Reset markers cannot reproduce a live Reset. Marius's reported live pause/replay mismatch remains unverified without the affected JSONL file.
- **Identity and pins:** the local-character marker and validated names can be missed when capture begins after the relevant metadata message. Reset totals retains identity, aliases, and pinned zero-total rows. New Start or connection selection clears current IDs and pin state to avoid reusing an unverified identity.
- **NPC and boss labels:** targets now show observed damage and evidence-based Player/NPC/Pet/Unknown categories, with search, highest-damage candidate selection, and optional manual labels/tags. This does not verify a boss. The decoder still does not extract a confirmed stable NPC template code; verify the spawn layout and catalog key before mapping game data to automatic boss and training-dummy names. Do not assume the displayed entity ID is a static mob ID.
